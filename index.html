Screen-space fluid rendering

Draws liquid particles as a smooth, shaded surface in the Blender viewport while the simulation plays.

I wrote the first version in OpenGL, then rebuilt it inside our native viewport library, so one Slang shader source serves Vulkan, OpenGL, Direct3D 12 and Metal. Particles are drawn as sphere impostors into depth and thickness targets. The depth is smoothed with a bilateral blur, and a final pass rebuilds normals and shades with Fresnel, Beer-Lambert absorption and a specular highlight. That pass writes depth as well, so the fluid sorts correctly against scene geometry.

The hard part was running several offscreen passes inside a host that already has its own render pass open.

nxMPM: multi-material MPM

A GPU Material Point Method solver for liquid, elastic solids, snow, sand, brittle solids, metal and foam, all on one shared grid.

I built the solver, with both an MLS-MPM and a CK-MPM implementation. It runs in Slang compute shaders on Vulkan and Metal, on a sparse grid, so memory follows the material.

Each frame takes as many substeps as the simulation needs. It also has mesh signed-distance colliders, sleeping for settled material, per-particle material parameters, and a mesh deformer that tears render meshes where the material is damaged.

Volume rendering for nxEFX

Live viewport preview of smoke, fire and explosions, with a fast slice mode and a lit ray-marched mode.

I implemented both modes in one Slang shader, cross-compiled for Vulkan, OpenGL, Direct3D 12 and Metal. Slice mode builds view-aligned polygons from plane-box intersections in the vertex shader, with no vertex buffer, and corrects opacity for slice spacing. Ray mode marches a 3D texture with empty-space skipping and early termination. It uses Henyey-Greenstein scattering, a shadow march toward the light, and blackbody emission for fire.

I ported it from an older preview that used a slower API, which sped it up and made it look better in the viewport.

Native viewport renderer and Dear ImGui host

A C++ library that draws simulation data inside Blender and Cinema 4D on Vulkan, OpenGL, Direct3D 12 and Metal, without a round trip through the CPU.

Simulation buffers are shared with the renderer as GPU memory: Vulkan external memory, OpenGL memory objects, or the same Metal buffer. Output goes straight into the host's own colour and depth targets. Direct3D 12 can't open Vulkan memory handles, so it gets a GPU-side mirror synchronised with a shared fence. Hosts that don't expose their device are handled by intercepting the graphics API in-process and recording our passes at a marker draw issued by the plug-in.

I wrote much of the library and the standalone Dear ImGui app. The app runs one simulation in side-by-side windows on different backends, so backend differences show up straight away. The renderer shipped as a viewport feature in Blender and Cinema 4D.

Gaussian splats in Blender (prototype)

Imports, renders, trains and simulates 3D Gaussian splats by treating each splat as a NeXus particle.

A weekend experiment. A modifier reads the standard 3DGS .ply, converts from COLMAP's coordinate basis to Blender's, and uploads the splats as particle attributes. An OpenGL renderer sorts them back to front every frame with a compute-shader bitonic sort and draws EWA-projected quads. Because they're particles, the usual forces, collisions and kill modifiers work on them. The second clip uses one to clear stray splats, sped up.

I also built a video-to-COLMAP capture pipeline and a differentiable rasteriser with an analytic backward pass, gradient-checked against a Python reference. The church scene was trained with gsplat.

Training an AI drone pilot in WebGPU

A neural network policy learns to fly a quadrotor in 3D, trained from scratch in the browser. Thousands of drones are simulated in parallel on the GPU, and the policy is optimised with evolution strategies, a gradient-free method for reinforcement learning tasks. Every drone gets a different mass and wind (domain randomisation), so the policy has to be robust. Physics, inference, ranking and the Adam update all run in WebGPU compute shaders.

Gaussian splats with MPM physics

Splats simulated as MPM particles in WebGPU. Pick jelly, sand, snow or liquid and the object drops and deforms. Each splat's covariance follows the material's deformation gradient, and the splats are depth-sorted every frame with a GPU radix sort. You can load your own .ply too.

GPU sorting in WebGPU and CUDA

A radix sort built on prefix sums and a bitonic sorting network, written in WGSL and ported to CUDA with the same structure. The demo sorts the shuffled pixels of a picture so you can watch each pass, benchmarks both sorts against the CPU and checks every result.
